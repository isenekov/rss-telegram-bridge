# Ручной тест Telegram без ожидания новых постов

Команда отправляет **одно синтетическое сообщение** существующим ботом в
указанный вами Telegram-канал. В сообщении нет данных пользователей Reddit:

> **ТЕСТ — проверка отправки в Telegram**
> https://github.com/isenekov/rss-telegram-bridge

Превью ссылки и звуковое уведомление выключены. Это проверка доступа к боту,
прав на публикацию, доставки, сохранения Telegram message ID и защиты от
повторного запуска. Она не доказывает работу Devvit → Telegram или одобрение
экспорта Reddit. Devvit-приложение остаётся в режиме чтения, его HTTP-доступ и
автоматическая отправка по-прежнему выключены.

## Запуск в Codespaces

Используйте существующий Codespace с Node.js 24 и ветку
`codex/devvit-readonly-20261112`. Терминал с playtest можно оставить открытым.
В другом терминале:

```bash
cd /workspaces/rss-telegram-bridge/devvit
git pull --ff-only
npm run telegram:test
```

Дополнительные зависимости не нужны. Только для просмотра текста без ввода
данных и без сетевых запросов: `npm run telegram:test -- --preview`.

Команда запросит два значения со **скрытым вводом**:

1. Токен существующего Telegram-бота, который используется для IGN/Eurogamer.
2. ID нужного канала вида `-100…` или его публичное имя вида `@channel_name`.

Вводите их только в запросы этой команды. Не передавайте секреты аргументами
командной строки и не присылайте их в чат. Значения не сохраняются в файлах,
переменных окружения или истории readline. GitHub Secrets не читаются и не
меняются: их существующие значения GitHub не раскрывает, поэтому здесь их
вводит владелец. Другой бот и ротация рабочего токена не требуются.

После ввода команда проверит бота и канал, выведет их имена и сразу выполнит
одну тестовую отправку, если этот тест ещё не выполнялся для данной пары
бот/канал. Бот должен быть администратором канала с правом публикации.

Успешный результат:

```json
{"event":"telegram_smoke","kind":"sent","messageId":42}
```

`messageId` будет фактическим ID из Telegram. Повторный запуск с теми же ботом и
каналом вернёт `already_sent` и не вызовет `sendMessage` повторно. Для повторного
запуска нужно снова ввести данные: токен не сохраняется.

## Ошибки и повторы

| Результат | Что означает |
| --- | --- |
| `already_sent` | Предыдущая отправка подтверждена, дубль не создан |
| `rejected`, код 400/401/403 | Telegram явно отказал; исправьте адрес/токен/права и повторите вручную после паузы |
| `rejected`, код 429 | Лимит Telegram; журнал учитывает `retry_after`, автоматических повторов нет |
| `cooldown` | Повтор пока заблокирован: минимум 60 секунд либо больший `retry_after` |
| `unknown` / `blocked` | Исход неоднозначен; сообщение уже могло прийти, повторная отправка заблокирована |
| `sent_unrecorded` | Telegram подтвердил сообщение, но записать результат не удалось; ID показан, повтор заблокирован |
| `state_unrecorded` | Результат не удалось записать; исходную запись попытки сохраняем, повтор блокируем |
| `busy` | Другой или незавершённый процесс удерживает блокировку |
| `error` | Проверка доступа или журнала не пройдена; сохраните только безопасный код ошибки |

При неоднозначном результате проверьте канал и сообщите строку `telegram_smoke`.
Не удаляйте журнал и не запускайте тест в новом Codespace для обхода блокировки.
Тайм-аут не является доказательством отсутствия отправленного сообщения.

## Как хранится результат

Журнал находится в `devvit/.telegram-test-state/` и исключён из Git. Он содержит
ID теста, ID попытки, время, результат и Telegram message ID; токен, название,
текст сообщения и ID канала туда не записываются. Имя каталога — хеш пары
бот/канал. Файлы создаются с правами 0600; запись попытки синхронизируется с диском
**до** `sendMessage`. Параллельные процессы используют эксклюзивную блокировку.

Гарантия повторов ограничена этим журналом в одном Codespace. При потере или
ручном удалении каталога новый запуск не узнает о предыдущем сообщении. Bot API
`sendMessage` не предоставляет ключ идемпотентности, поэтому обещания
«ровно один раз при любом сбое» здесь нет. Неоднозначная попытка требует проверки
владельцем. Только явный отказ Telegram допускает последующий ручной повтор.

Ни `posted.json`, ни Redis приложения, ни рабочие RSS-workflow этим тестом не
читаются и не изменяются. Команда не подключена к GitHub Actions или Scheduler.

## Перед реальным Reddit → Telegram

Остаётся получить подтверждение допустимости использования, настроить секреты
и HTTP-разрешение уже в Devvit, связать транспорт с очередью Redis и проверить
доставку/удаление на отдельной тестовой установке. Синтетический тест не заменяет
эти шаги и не включает отправку накопленных Reddit ID.

Документация: [Telegram Bot API](https://core.telegram.org/bots/api#sendmessage),
[Devvit HTTP Fetch Policy](https://developers.reddit.com/docs/capabilities/server/http-fetch-policy).
